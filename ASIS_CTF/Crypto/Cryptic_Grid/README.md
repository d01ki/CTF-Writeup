このプログラムは、AES-ECBモードの性質と、線形合同法（LCG）による状態遷移、そしてサイドチャネル的な情報漏洩を組み合わせた暗号パズルです。

🛠 スクリプトの構造解析このプログラムの核心は以下の要素にあります。
Core（核心）: 0 から 63 までの数字をランダムに並べ替えた64バイトのデータ（Permutation）。
これを見つけ出すことがゴールです。
Grid（格子）: wrap(インデックス): wrap(core[値]) という形式の辞書。
キーも値もAES-ECBで暗号化されています。wrap関数: AES-ECBを用いて、16バイトブロックとして暗号化/復号します。キーは「Alignment（アライメント）」が発生するたびに新しく生成されます。Focus（フォーカス）: 現在ターゲットとなっている 0-63 の数値。コマンド:s (Shift): Focusを (focus * 5 + 3) & 0x3F で更新。q (Query): 任意の entry（暗号化されたインデックス）と delta を送り、その先の値を調査。r (Reflect): 任意のデータの暗号化または復号。コストが高い（8回分消費）。c (Check): core を当てればフラグ獲得。

🚩 フラグ奪取戦略： "Focus Alignment Oracle"最大試行回数が 42 回と非常にタイトですが、「Alignment Found」が発生すると試行回数が MAX_ATTEMPTS (42回) にリセットされるという仕様を悪用します。1. Focusの予測まず s を1回実行して現在の focus を取得します。Focusの遷移式 $f_{n+1} = (5f_n + 3) \pmod{64}$ は既知であり、法が $2^6$、係数が条件を満たしているため、周期64のフルサイクルです。つまり、s を叩くたびに次に現れる focus の値は完全に予測可能です。2. インデックスの固定r コマンドで数値 0 を暗号化し、E0 = wrap(0) を入手します。これ以降、q コマンドで entry=E0 を使うと、内部的な idx 計算は次のようになります：$$idx = (0 + delta + 32) \pmod{64}$$つまり、delta を -32 から 31 まで変化させることで、すべてのインデックス 0-63 を自在に指定して core[idx] を調査できるようになります。3. 全Coreデータの復元（ループ戦略）以下の手順を繰り返します。ターゲットの特定: 現在の focus を $F$ とします。線形探索: q(E0, delta) を delta を変えながら呼び出します。Alignmentの検知: もし core[idx] == F であれば、サーバーは "ALIGNMENT FOUND at {idx}" と返します。これで core[idx] = F であることが確定します。同時に Attemptsが42にリセットされます。状態のリセット: アライメントにより key が変わるため、再度 r で新しい E0 を取得し、s で新しい focus に切り替えます。続行: まだ判明していない core の値を埋めるまで繰り返します。4. 仕上げ64個すべての core[idx] が判明したら、それらを順番に並べて bytes に変換し、16進数文字列（hex）として c コマンドに送信すれば、フラグがアンロックされます。

💡 攻略のポイント試行回数の管理: r (8回) + q (平均32回) = 約40回。

初期値の42回以内に次の Alignment を見つける必要がある、絶妙なゲームバランスになっています。

情報の活用: q が Alignment しなかった場合でも、Trace: {out} として wrap(core[idx]) が返されます。これらを記録しておけば、r を使わずに済むケースもあり、効率化が可能です。
